# VYLO

## الموقع المنشور والربط المجاني الحالي

[افتح VYLO](https://ahmednasser667748-cyber.github.io/VYLO-landing/).

الواجهة منشورة على GitHub Pages. `public/bridge.js` يرسل الفورم مباشرة إلى Google Apps Script ويقبل إيصالًا من نطاق جوجل مطابقًا لرقم المحاولة قبل التحويل إلى واتساب. لا يحتاج هذا المسار إلى خادم Node أو Render. النسخة السابقة من خادم Node محفوظة كخيار استضافة بديل.

داخل مشروع جوجل: `Code.gs` و`Public.gs` وmanifest. المفتاح في Script Properties باسم `TELEGRAM_BOT_TOKEN`، و`BRIDGE_SECRET` يحمي عنوان Webhook الإداري. تشغيل `setupPublicVylo` يربط البوت بنفس نشر السكربت. الردود تُعالج عند وصول Webhook، دون جدولة كل دقيقة. لا تُرسل مفاتيح إلى المتصفح. لا تشغّل polling من خادم Node مع الـWebhook الحالي.

اختبار الموقع العام `VY-53CE31DD22E9` سجّل الطلب في الشيت وأرسل رسالة تليجرام رقم 8 ثم فتح واتساب. اختبار Webhook بوارد مُحاكى أرسل سؤال إدخال المبلغ رقم 9، وسجّل 100 جنيه تجريبية: إجمالي 419 وباقي 319، وأقر تليجرام تعديل رسالة الأوردر. بيانات الاختبار خيالية ولا تمثل دفعًا. لم يُختبر الضغط البشري من هاتف المالك؛ الوارد كان محاكاة، بينما الكتابة والرسائل والتعديل حية.

Google Apps Script وTelegram يخضعان لتوافر الخدمة وحصص الاستخدام؛ Webhook يلغي انتظار الجدولة ولا يضمن زمن استجابة ثابتًا. إذا سجل الشيت إرسالًا بحالة `uncertain` فراجع تليجرام قبل إعادة الإرسال. الطلب العام يستخدم رقم المحاولة لمنع التكرار ويعيد حساب السعر داخل جوجل.

لاندنج بيدج عربية بهوية VYLO وصورها وفيديوهين من صفحتها، مع API خاص للطلبات وبوت لتسجيل الديبوزيت في Google Sheets.

## التشغيل

يتطلب Node.js 22.13 أو أحدث، ويفضل Node.js 24. لا توجد مكتبات تحتاج إلى تثبيت.

```sh
node server.mjs
```

المعاينة: `http://127.0.0.1:4173`. دون إعداد الأسرار وربط الشيت، الصفحة تعمل للمعاينة ويُرفض تسجيل الطلبات بأمان.

للتشغيل الفعلي، اضبط المتغيرات في إعدادات الاستضافة. يمكن محليًا نسخ `.env.example` إلى `.env` ثم:

```sh
node --env-file=.env server.mjs
```

- `TELEGRAM_BOT_TOKEN`: مفتاح البوت في إعداد خاص، خارج ملفات الموقع.
- `TELEGRAM_CHAT_ID`: `6405303283`.
- `TELEGRAM_ADMIN_ID`: حساب الشخص المسموح له بتأكيد الديبوزيت، حاليًا `6405303283`.
- `TELEGRAM_POLLING`: `true` لاستقبال ضغطات الأزرار والردود. يشترط عدم وجود webhook آخر لنفس البوت. التطبيق يفحص ذلك ولا يمسح أي webhook موجود.
- `SHEETS_BRIDGE_URL`: رابط نشر Apps Script المنتهي بـ `/exec`.
- `SHEETS_BRIDGE_SECRET`: مفتاح خاص مشترك مع السكربت، ويمكن تركه فارغًا عند استخدام الاشتقاق التلقائي بالمشروع الحالي.
- `SHEETS_BRIDGE_CONTEXT`: سياق علني خاص بمشروع VYLO. عند غياب المفتاح الصريح، يشتق الخادم مفتاح HMAC منفصلًا من مفتاح البوت وهذا السياق. المفتاح الأصلي للبوت لا يُرسل إلى جوجل. تغيير مفتاح البوت يستلزم تحديث المفتاح المشتق داخل Script Properties أيضًا.
- `ALLOWED_ORIGIN`: أصل صفحة البيع النهائي إذا اختلف عن الخادم، مثل `https://example.github.io`.
- `PORT` و`HOST`: المنفذ والعنوان حسب الاستضافة. لخادم خلف reverse proxy أو منصة استضافة استخدم `HOST=0.0.0.0` وفق إعداداتها.
- `VYLO_DATABASE_PATH`: مكان قاعدة SQLite الدائمة. الافتراضي `.data/orders.sqlite`. احتفظ بها على وحدة تخزين دائمة وخاصة.

## شيت الطلبات

تم إنشاء شيت فعلي في الحساب المتصل:

[VYLO — الطلبات والديبوزيت](https://docs.google.com/spreadsheets/d/1byEfZMV_LbPqVhOY_tmLNi_ajvBm0pdGjQ8rZKG0NCo/edit)

`Orders` يسجل بيانات الطلب والمدفوع والباقي والحالة. `Payments` يحتفظ بسجل كل تعديل مدفوع، بقيمته السابقة والجديدة. أعمدة الإجمالي والباقي محسوبة داخل الشيت أيضًا.

تم نشر السكربت بحساب مالك الشيت وتفعيل توقيع الطلبات، واختباره حيًا من الفورم إلى الشيت وتليجرام ثم واتساب. رابط النشر موجود في `.env.example` وتفاصيله العامة في `apps-script/project.json`. المفتاح الخاص محفوظ في Script Properties، ويشتقه الخادم تلقائيًا من مفتاح البوت عند ترك `SHEETS_BRIDGE_SECRET` فارغًا.

خطوات إعادة الإعداد إذا نُقل المشروع إلى حساب جوجل أو بوت مختلف:

1. من الشيت: Extensions → Apps Script.
2. ضع محتوى `apps-script/Code.gs` في المشروع، واضبط إعدادات manifest وفق `apps-script/appsscript.json`.
3. ضع مفتاح الربط في Script Properties باسم `BRIDGE_SECRET`. يمكن استخدام قيمة مشتقة عبر `deriveBridgeSecret` في `sheets.mjs`، أو مفتاح عشوائي مستقل يُضبط أيضًا في الخادم باسم `SHEETS_BRIDGE_SECRET`. لا تضع المفتاح داخل الكود أو GitHub.
4. شغّل `setupVyloSheet` مرة واحدة. يثبت معرف الشيت في Script Properties ويجهز التنسيق، من دون حذف الطلبات.
5. انشر Web app يعمل بحساب مالك الشيت. يحتاج الخادم للوصول إلى نقطة الاستقبال؛ جميع عملياتها تتطلب توقيع HMAC خاصًا صالحًا، ولا يوجد فيها عرض عام لبيانات العملاء.
6. ضع رابط `/exec` في `SHEETS_BRIDGE_URL`، وشغّل الخادم بمتغيراته الخاصة.
7. اختبر طلبًا جديدًا، ثم اضغط زر الديبوزيت من حساب تليجرام المصرح له وأدخل مبلغًا تجريبيًا. يجب مراجعة صف الطلب وسجل الدفعات قبل اعتماد التشغيل التجاري.

## سلوك الطلب والديبوزيت

1. الخادم يتحقق من الاسم والهاتف المصري والمحافظة والعنوان وأسماء الأطفال، ويحسب المبالغ من الكتالوج.
2. يسجل الطلب في الشيت، ثم يرسل أوردرًا لتليجرام مع زر «تأكيد ودفع ديبوزيت» وزر التواصل مع ولي الأمر.
3. بعد التأكد من الشيت وتليجرام، يفتح واتساب برسالة جاهزة. العميل يرسل الرسالة والصور بنفسه.
4. ضغط زر الديبوزيت يرسل سؤالًا مربوطًا بالأوردر. يجب الرد على رسالة السؤال نفسها بالمبلغ.
5. المبلغ المدخل هو **إجمالي المدفوع حتى الآن**، ويستبدل القيمة السابقة. لا يُضاف مرة ثانية عند إعادة الإرسال.
6. البوت يحدث الشيت أولًا. بعد تأكيد الكتابة يرسل رسالة نجاح ويحدّث زر الأوردر. المبلغ المقبول أكبر من صفر وحتى إجمالي الطلب، بدقة قرشين.

قاعدة البيانات تحفظ أرقام المحاولات وحالتها وبيانات الطلب اللازمة لإدارة الأزرار. تُستثنى `.data` وأي `.env` من GitHub. إعادة نفس المحاولة لا ترسل أوردرًا جديدًا؛ أما حالة انقطاع الاتصال التي يتعذر فيها التأكد من استقبال تليجرام فتتوقف للمراجعة بدل تكرار الإرسال.

مستودع المشروع: [VYLO-landing](https://github.com/ahmednasser667748-cyber/VYLO-landing). مجلد `public` مناسب لاستضافة الواجهة، ومنها GitHub Pages. خادم Node والبوت يحتاجان استضافة خلفية دائمة؛ GitHub Pages لا يشغّل السيرفر أو يحتفظ بمفتاح البوت. عند فصل الواجهة، اضبط `apiBase` في `public/config.js` و`ALLOWED_ORIGIN` على الخادم. رفع المصدر إلى GitHub وحده لا ينشر خدمة استقبال الطلبات.
